## v1.2.0（2026-10-31）

导入互操作：Markdown 批量导入、富文本粘贴转 Markdown、Evernote/Notion 导入器——给二手数据体面的「进场」通道（F-801/F-802/F-803/F-804）。全部导入为**全量插入**（不与既有笔记合并、无跨库去重），完成后弹窗输出统计摘要。

### 功能

- **F-801 Markdown 批量导入**：数据菜单「导入文件」+ 整页拖拽——多选 .md 与 zip 包（`notes/` + `assets/` 目录结构）。标题取首个 H1（缺失回退文件名）；zip 顶层 `notes/` 视为容器不建文件夹，其下一级目录映射单层文件夹，二级目录起平铺（层级以标题前置保留在一篇内）；包内图片按「原文/解码/文件名」三键匹配重链为内部附件（图片白名单 + 10MB 上限，超限计入跳过）
- **F-802 富文本粘贴转 Markdown**：编辑器 capture 阶段拦截 text/html 粘贴（turndown + GFM 插件动态 import 惰性加载）：标题/列表/表格/加粗/斜体/链接/行内代码/删除线/任务列表映射；`data:` 内嵌图片走 v0.3 附件管线、http(s) 保留外链、file:/blob: 等浏览器不可达引用丢图；html 无正文文本而文件含图片（截图/独立图片复制）仍走纯图片管线；**Ctrl/Cmd+Shift+V 保持纯文本粘贴**；转换失败回退纯文本插入
- **F-803 Evernote ENEX 导入器**：DOMParser 解析 ENML → 复用 F-802 转换内核；`<resource>` 图片白名单落附件（en-media hash 占位重链，非图片转占位提示）；`<en-todo>` → 任务列表；来源 URL 写入正文首部 blockquote（不新增字段）；原生标签直接映射；创建/更新时间随 ENEX 带入；文件名（去 .enex）映射文件夹
- **F-804 Notion 导出 zip 导入器**：嵌套子页平铺内联进父页正文（标题层级随深度降级、超 6 级封顶），页间 md 链接降噪为纯文本；附件按相对路径/文件名重链；数据库 csv → 每行一篇笔记（名称列 → 标题、文本属性映射标签、日期属性映射创建/更新时间、公式列取纯文本进属性表、空行跳过并计数）；`Untitled` 空壳页跳过
- 入口与反馈：导入弹窗展示成功/跳过/失败计数与明细，进行中忽略新触发；完成后列表/文件夹/派生索引（搜索 + 链接）整库刷新（与备份恢复同口径）

### 修复

- **F-102 自动保存竞态导致键入内容静默丢失（v0.1 起即存在，E2E 冒烟首套发现）**：persist 在 `await saveChanges(...)` 恢复后才把 `savedContent` 标记为 `content.value`——保存落库期间继续键入的内容被误标为「已保存」，后续 flush 全部走跳过分支，刷新后丢失。修复：persist 入口先快照草稿，标记的是**本次实际保存的快照**，保存窗口内的新键入由下次 flush 补存

### 工程线（E-01/E-02/E-05，v1.2 搭车）

- **E-02 Playwright E2E 首套落地**：`npm run e2e`——冒烟（新建 → 编辑 → 刷新存续 → 导出全量备份 → 清空全部数据 → 备份还原全链路）+ 导入链路 4 例；跑在构建产物上（vite preview，CI 注入 VITE_BASE 时按子路径换算）；已纳入 deploy 流水线门禁（test:run → build → e2e → 发布）。首套即抓出 F-102 竞态真 bug
- E-01 打包纪律：turndown + GFM 动态 import（独立 chunk gzip ≈5KB，仅首次富文本转换加载）；导入模块并入 index chunk（gzip +6.8KB）；**gzip 总计 ≈495KB，0.5MB 基线不回退**
- **E-05 F-504 本地文件夹直连：决策继续搁置**——File System Access API 仍限 Chromium 系；导入管线已覆盖「外部 md 库进场」核心收益；双向落盘的冲突面与维护成本高于当前反馈价值（ROADMAP §10.6 已记录，留待真实需求重启）

### 数据 schema

- **无变更（仍为 schema v4）**；备份/同步/快照格式不变（导入产物即普通笔记/附件/文件夹）

### 测试

- 新增单测 40 例（较 v1.1 +40）：csv（RFC4180 口径）、markdownImport（标题提取/目录映射/图片重链）、enexImport（解析口径/ENML 转换/紧凑 UTC 时间）、notionImport（去标识/标题降级/页面树装配/csv 数据库）、importService（四类入口端到端，fake-indexeddb 走真实 Dexie 路径）

### 已知问题 / 范围外

- 导入不做智能合并与跨库去重（§10.2 口径）：同名笔记重复导入会产生两份
- F-801 直选 .md（非 zip）场景图片链接保留原文（无资源可重链）；zip 内未命中资源的图片引用同样保留原文
- 本地 Word 桌面版复制的内嵌图片为 file: 引用（浏览器不可达）不自动落附件；Word 网页版 https 图保留外链、data: 图落附件库

- Notion csv 无类型信息：日期列按「全列可解析」启发式判定，文本/公式列均按纯文本处理

## v1.1.0（2026-10-28）

知识连接：双链（Wiki Links）、出入链接面板、关系图谱——把「文件夹/标签的分类式组织」升级为「笔记间的显式连接」（F-701/F-702/F-703）。

### 功能

- **F-701 双链协议与解析**：正文 `[[标题]]` / `[[标题|别名]]` 纯 Markdown 文本约定（双链 = 正文字符串，无 schema 变更，天然随备份/同步/快照全链路工作）：
  - 解析口径（`features/links/wikilinks.ts`）：标题精确匹配（大小写敏感）、别名可空（`[[标题|]]` 也算引用）、超长（>200 字符）与含换行不匹配、围栏代码块与行内代码内跳过、`![[…]]`（v1.4 前不支持的嵌入语法）按纯文本处理。
  - 预览渲染（markdown-it 内联规则，注册于 link 之前）：不进 link token 的 `[[ ]]` 文本独立扫描渲染为锚点（`data-wikilink`，展示别名 || 目标，全部 HTML 转义）；导出 `.md` 与备份保留原文字面量（遵循 Obsidian 等通用约定）。
  - 预览内点击：命中唯一 → 路由跳转目标笔记；同名多篇 → 候选列表消歧弹层（Esc/遮罩关闭）；未命中 → **点击新建同名笔记**消除断链（与预览、出链行三处共通）。
  - 编辑器补全：输入 `[[` 唤出标题补全浮层（CodeMirror 扩展缝 setup.ts，候选 = 库中活跃笔记标题去重，按最近更新倒序，↑↓/Enter/Esc 键盘导航，补全落笔 `[[标题]]`）。
  - 重命名迁移：标题草稿与已落库基线不一致、且旧标题仍被 `[[ ]]` 引用时，标题栏下方出现迁移条——**「更新全部引用」一键迁移**（repository `replaceTitleReferences` Dexie 单事务全库游标替换 `[[旧标题]] → [[新标题]]`，保留别名部分，失败不落库），或「忽略（保留旧引用）」× 留断链；迁移后清正文缓存、按篇重录搜索索引、链接索引整批重建、列表刷新（excerpt 同步重算）。
- **F-702 出入链接面板**：编辑器侧栏新增「链接」页签（预览态「大纲」常显旁，工具栏按钮切换）：**反链**（引用了当前笔记的活跃笔记列表，逐条 ±40 字引用行摘要，按最近更新排序，与搜索摘要同口径）+ **出链**（当前笔记 `[[ ]]` 引用的目标，断链琥珀色标记；点击断链走新建同名笔记，命中行直接跳转）。链接索引为**内存派生数据**（`linkIndex.ts`，与 MiniSearch 索引同原则）：正文正则流式扫描构建，保存/新建/恢复增量维护、软删/彻底删除摘除、同步整库改写后丢弃择机重建、回收站笔记不产生有效出链；不落库、可随时重建，变更经 store 版本代数驱动面板/图谱响应式重算。
- **F-703 关系图谱**：新增 `/graph` 路由（侧栏底栏与回收站并排入口 + 命令面板「打开关系图谱」命令），**自研轻量力导向图**（SVG + requestAnimationFrame + 黄金角螺旋确定性初始布局，零图库依赖，未引入 D3）：
  - 节点 = 笔记：按文件夹着色（6 色系与主题预设同族，未分类中性灰；图例随当前子集）、半径按链接度（√degree，5–16px）；边 = 双链（有向解析、去重、断链与自环不产生边，孤立节点保留）。
  - 交互：点击节点跳转该笔记、hover 高亮邻接（非邻接淡出 + 邻接边高亮层）、滚轮以指针为锚缩放（0.3–4×）、拖空白处平移、节点拖拽固定坐标（位移 <4px 视为点击）、「复位视图」按节点包围盒自适应。
  - 大库降级（§10.1）：默认仅渲染**当前过滤子集**（文件夹/标签/搜索，≤ 500 节点；超出按「链接度 → 最近更新」截断并琥珀提示）；「全库」模式切换前显式确认阈值与冻结风险（确认后 4s 内不重复弹窗）。
  - 数据复用 F-702 链接索引（内存派生数据，`graphData.ts` 纯函数装配便于单测）；力仿真坐标不经 Vue 响应式——rAF 逐帧直写节点 transform 与边 path，500 节点量级不掉帧；数据重建同 id 节点热启动保持现位、温和重热，保存路径反复触发不抖动。

### 工程线（E-01 打包拆分，v1.1 搭车）

- manualChunks 落地：vendor（vue/router/pinia/vueuse/dexie/fflate）/ editor（CodeMirror）/ markdown（markdown-it + hljs）/ minisearch / virtual（vue-virtual）分 chunk，产物粒度利于缓存与增量更新。
- **MiniSearch 动态 import**：仅 ≥5000 篇触发的倒排索引库改为构建期惰性加载（`buildIndex` 异步时点拉取，加载期查询照常回退流式扫描，无功能空窗）；小库（绝大多数用户）永不下载该 chunk。
- GraphView 走路由级分包（进入 /graph 才加载，gzip 5.0 kB）。
- 基线核对：**gzip 总计 ≈ 489 kB，未回退**（≤ 0.5MB 门槛保持，v1.0 为 0.46MB，增量为本版双链/图谱功能本体）。

### 数据 schema

- **无变更（仍为 schema v4）**；备份/同步/快照格式全部不变（双链即正文字面量，天然兼容）
- 无新增 localStorage key、无新增 i18n 之外存储

### 测试

- 新增单测 49 例（较 v1.0 +49）：wikilinks（解析口径/断链/自环/`![[`嵌入/代码块跳过/摘要/render 转义/重命名替换保留别名，18 例）、wikilinkComplete（候选过滤/落笔，6 例）、linkIndex（增量/摘除/重建/构建期补账/同名去重，6 例）、graphData（装配：有向边与度数/断链与孤立节点/同名解析/自环去重/截断口径/默认 500 上限/空库，8 例）、forceLayout（弹簧收敛/斥力防重合/alpha 乘法衰减与重热/seed 热启动/断端防御/500 节点无 NaN/确定性复现，8 例）、既有 noteRepository 等用例扩展（重命名迁移事务路径，3 例）
- 全量 `npm run test:run` **319 用例**通过（较 v1.0 270 例 +49）；`npm run build`（vue-tsc 类型检查前置）通过，PWA 产物正常

### 已知问题 / 范围外

- **E-01 余项**（观察项延续，见 ROADMAP §10.1/§10.6）：vue-virtual 惰性挂载（需把长列表抽成异步子组件，仅 >300 笔记用户受益）与 i18n 字典拆载（同步 t() 语义需预载，影响测试基建与首屏路径）本版不做；两者收益小、风险中等，等 v1.2+ 大依赖（turndown/Readability）进场时一并评估

## v1.0.0（2026-10-24）

打磨与扩展：中英双语（i18n）、命令面板插件化命令注册、万级笔记性能上限与扩展点评估（ADR-011）。

## v0.6.0（2026-10-24）

同步与多设备：GitHub Gist 全量同步、冲突处理与可选端到端加密——两台设备之间数据可达，仍不引入任何自建服务器。

### 功能

- F-501 GitHub Gist 同步：设置面板新增「同步（GitHub Gist）」区——粘贴具备 gist 权限的 PAT（仅存本机 localStorage）即可启用；首次同步自动创建私有 Gist（单文件 `tinynote-sync.json`，secret），此后 PATCH 更新同一文件；支持设备名（冲突副本署名）与「启动时自动同步」开关（默认开启，进入应用自动触发一轮，失败只体现在面板状态不阻塞首屏）；手动「立即同步」随时可用，同步完成后列表/文件夹/编辑器自动刷新
- F-502 冲突处理：以上次同步成功的库状态指纹为基线做三方合并——只有一侧变更采纳该侧；双侧都变更时 `updatedAt` 较新者胜（last-write-wins，平局本地胜），**落败方完整保留为冲突副本笔记**（`标题（冲突@设备名）`，附件引用重映射到独立的新附件行）供手动合并；一侧删除另一侧修改时**修改优先于删除**；远端删除且本地未动则物理删除传播（其遗留历史快照一并清理）；回收站/标签/置顶/文件夹归属变化均参与合并判定（指纹不含 updatedAt，时间戳漂移不误判）
- F-503 同步加密（可选）：Web Crypto AES-GCM-256，密码经 PBKDF2-HMAC-SHA256（600k 轮）派生密钥，每次加密换随机盐与 IV；开启后 Gist 上只有不可读信封（`tinynote-sync-enc`），GitHub 侧无法看到笔记内容；密码遗失无法解密远端（面板有提示）
- 同步安全语义：基线（settings KV `syncBaseline`）只在「落库 + 上传」都成功后写入，任一步失败不会让下一次同步误判变更方向；断开同步只清除本机配置与基线，远端 Gist 与笔记数据不动；「清空全部数据」会连同基线与同步配置一并清除

### 数据 schema

- **IndexedDB schema 无变更（仍为 v4）**；settings KV 新增 `syncBaseline`（上次同步的逐笔记/逐文件夹状态指纹，FNV-1a 双种子 16 hex）
- 新增同步载荷格式 **SyncFile schemaVersion 1**（`tinynote-sync`）：全量库 JSON（folders + notes 含正文 + 附件 base64 内联），与备份格式（schemaVersion 2 zip）相互独立、互不影响；加密信封（`tinynote-sync-enc`：salt/iv/ciphertext）为其外包装
- backupPort 新增 `applySyncLibrary`：同步合并结果单事务全量覆盖 notes/contents/folders/attachments（**不触碰快照与 settings**，区别于备份恢复的覆盖语义）；快照不参与同步（本机编辑历史）
- 同步配置（PAT/Gist id/设备名/加密开关/密码/自动同步/设备标识）存 localStorage `tinynote:sync:*`（架构文档 4.3 双存储分工口径）

### 测试

- 新增单测：base64 分块互转（二进制安全/Blob 往返）、sync（载荷校验与版本拒绝/状态指纹稳定性/LWW 首轮合并/三方合并各分支/冲突副本与附件重映射/删除传播与复活/回收站状态参与合并/文件夹合并与悬空 folderId 回退/载荷与基线构建往返）、syncCrypto（加解密往返/错误密码/密文篡改/参数校验）、gistClient（鉴权头/文件缺失→空远端/401·404 错误映射/创建与 PATCH/网络失败）、syncStore（首轮自动建 Gist 与基线/未配置与远端失败路径/远端笔记落地并刷新视图/冲突副本落库/远端删除传播/加密端到端回放/自动同步开关/disconnect）
- 全量 `npm run test:run` **248 用例**通过；`npm run build`（vue-tsc 类型检查前置）通过，PWA 产物正常

### 已知问题 / 范围外

- **F-504 本地文件夹直连（探索项）本版未实施**，保留编号留待评估（ROADMAP §8）
- 首次同步（无基线）为纯 LWW、不生成冲突副本：两台各自已有数据且分叉较大的设备首次对接时，同篇笔记较旧一方的改动会按 LWW 语义落败（UI 提示先备份）；正常连续同步始终有基线，冲突副本机制完整生效

- 加密密码存本机 localStorage（换取启动自动同步免输密码）：威胁模型为「Gist 内容在 GitHub 侧不可读」，不防御本机已沦陷的场景

### 数据 schema

### 已知问题 / 范围外
