# TinyNote 功能点迭代文档

> 版本：v1.1 ｜ 日期：2026-10-27 ｜ 状态：已定稿（v0.1–v1.0 各版本章节为已实现定稿；§10 为「后 v1.0 阶段」规划稿）
> 配套文档：[技术架构文档](./ARCHITECTURE.md)

---

## 1. 迭代原则

1. **每个版本独立可用、可发布**：不做半成品功能进主线；一个版本 = 一次 git tag + CHANGELOG 记录。
2. **数据安全优先于新功能**：任何版本发布前，"导出备份"链路必须可用；先保证不丢数据，再谈加功能。
3. **数据 schema 只增不破**：新字段一律可选（`?`），旧数据经迁移函数升级；备份格式带 `schemaVersion`，导入向后兼容。
4. **小步快跑**：每版 2–4 周量级；功能点带编号（F-xxx），变更与砍掉的功能记录在 CHANGELOG，避免范围膨胀。
5. **每版有可验收标准**：功能点描述"做完长什么样、怎么测"，验收不过不发布。

## 3. v0.1 —— MVP：能记

> 目标：跑通"记录 → 自动保存 → 找回"闭环，上线第一个可用版本。

| 编号 | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F-101 | 笔记新建/编辑/删除 | textarea 编辑器 + 标题栏；删除走确认弹窗，数据层软删（`trashed`），为 v0.2 回收站铺路 | 新建出现空笔记并可输入；删除后从列表消失且库中留痕 |
| F-102 | 自动保存 | 输入防抖 800ms 写库 + 失焦立即保存 + 关页强制 flush；无保存按钮 | 输入后**不点任何按钮**直接刷新页面，内容仍在 |
| F-103 | Markdown 实时预览 | 编辑/预览分栏或切换；支持 GFM 基础：标题、列表、代码块、链接、引用 | 常见语法渲染正确；原始 HTML 不被执行（安全要求） |
| F-104 | 笔记列表 | 按 `updatedAt` 倒序；展示标题 + 内容摘要 + 相对时间 | 新建排序置顶；摘要截断无样式泄漏 |
| F-105 | 全文搜索 | 大小写不敏感的包含匹配，命中标题与正文，标题命中优先 | 搜索词能命中标题笔记与正文笔记；输入防抖不卡顿 |
| F-106 | 主题 | 深浅色跟随系统（`prefers-color-scheme`），可手动切换 | 切换即时生效并持久化 |
| F-107 | 数据落库 | Dexie/IndexedDB schema v1（见架构文档 4.2） | 重复打开应用数据稳定；DevTools 可见 notes 表 |

**本版明确不做**：文件夹、标签、回收站 UI、导出、PWA。
**发布门槛（E2E）**：新建→输入→刷新数据在；导出 JSON→清库→导入还原（手动走一遍）。

## 8. v0.6 —— 同步与多设备（已实现）

> 目标：两台设备之间数据可达，仍不引入任何自建服务器。（原 v0.5 段顺延，F-5xx 编号不变）

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-501 | GitHub Gist 同步 | 用户配置 PAT（存本机），把全量数据（可加密）存入私有 Gist；手动/进入时自动触发同步 | settings 新增同步基线 KV |
| F-502 | 冲突处理 | 以 `updatedAt` 为准 last-write-wins；检测到双侧都变更时保留冲突副本（`<标题>(冲突@设备)`）供手动合并 | 冲突副本即普通笔记，无 schema 变更 |
| F-503 | 同步加密（可选） | Web Crypto AES-GCM，密码经 PBKDF2 派生密钥后加密备份内容再上传 | Gist 内容格式新增加密包装 |
| F-504 | 本地文件夹直连（探索，**本版未实施**） | File System Access API 把笔记库指向本地文件夹（.md 文件直接落盘）；浏览器支持度有限，标注实验特性 | 视结果决定是否转正 |

**验收要点**：两台设备（或两个浏览器 Profile）通过 Gist 完成一次双向同步且无静默数据丢失；加密开关打开后 Gist 内容不可读。

**v0.6 实现口径补充**：

- **载荷**：全部数据存于一个 secret Gist 的单文件 `tinynote-sync.json`（SyncFile，schemaVersion 1）——全量库 JSON，附件以 base64 内联（Gist 只收文本）；与备份格式（schemaVersion 2 zip）相互独立。首次同步自动创建私有 Gist，此后 PATCH 增量更新同一文件。
- **合并算法**：以上次同步成功时的逐笔记/逐文件夹状态指纹（FNV-1a 双种子，settings KV `syncBaseline`）为基线做三方判定——只有一侧变更→采纳该侧；双侧都变更→`updatedAt` 较新者胜（平局本地胜），落败方完整保留为冲突副本笔记（附件引用重映射到复制出的新附件行）；一侧删除另一侧修改→**修改优先于删除**；远端删除且本地未动→物理删除传播。指纹不含 `updatedAt`（时间戳漂移不算变更，软删/标签/正文/文件夹变化均可检出）。
- **首次同步（无基线）**：纯 LWW、不生成冲突副本（无法判定双侧改动方向）；UI 提示先「导出全量备份」再开始。基线只在「落库 + 上传」都成功后写入，任一步失败不会让下次同步误判。
- **同步范围**：全量笔记（含回收站）+ 文件夹 + 附件；历史快照（F-402）与设置 KV 不参与同步（与备份口径一致）。合并落库走 `backupPort.applySyncLibrary`（单事务全量覆盖四表，快照保留；被远端删除笔记的遗留快照一并清理）。合并改写了库内容时通知列表/编辑器刷新（编辑器重建重读正文，避免旧草稿覆盖远端写入）。
- **安全与隐私**：PAT/加密密码仅存本机 localStorage；加密为 AES-GCM（256 位），密码经 PBKDF2-HMAC-SHA256 600k 轮派生，每次加密换随机盐与 IV；开启后 Gist 上只有不可读信封。
- **文件夹**：无时间戳，双侧同时改名时保留本地（记录于 CHANGELOG 已知问题）；文件夹删除传播后引用它的笔记回退未分类。

## 9. v1.0 —— 打磨与扩展（已实现）

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| F-601 | i18n | 中/英双语，文案层抽离（**已实现**） |
| F-602 | 外观定制 | 主题色、字体、字号、编辑区行宽设置（**已提前至 v0.5 实现，见 F-521**） |
| F-603 | 命令面板 | `Ctrl+P`：搜索笔记 + 执行命令（**搜索主体已提前至 v0.5 实现，见 F-524**，Ctrl+K 唤起；**命令注册机制已在本版落地**） |
| F-604 | 性能上限 | 万级笔记：列表虚拟化、启动时间预算（首屏 < 1.5s）、切换 MiniSearch 倒排索引（**已实现**） |
| F-605 | 扩展点评估 | 沉淀命令/编辑器插件接口，为社区扩展铺路（**已实现：ADR-011 扩展点评估落地**） |

**v1.0 实现口径补充**：

- **F-601 i18n**：中文（zh-CN）为源语言字典，英文为翻译字典；`t()` 为响应式取词（模板/计算属性中调用即随语言切换重渲染），`{name}` 占位符插值，缺失 key 回退链 当前语言 → zh-CN → key 本身。语言偏好存 localStorage `tinynote:locale`（默认跟随 `navigator.language`）；设置面板新增「界面语言」切换，命令面板提供切换命令。字典齐平与「使用中 key 全量存在」由单测静态扫描保证（i18n.spec 直接读取源码校验 `t('...')` 字面量）。时间格式化（toLocaleString）随语言切换（zh-CN ↔ en-US）。
- **F-603 命令注册机制**：命令面板动作来源从硬编码改为 `useCommandRegistry`（Pinia）——`register/unregister/get`，重复 id 覆盖（热更新语义），title 为取词函数（渲染时求值、随语言切换），支持 keywords 额外匹配词。内置 7 个命令（新建/回收站/深浅色/行号/设置/语言/导出备份），`Ctrl+P` 与 `Ctrl+K` 等价唤起。该注册表即 F-605 的第一个扩展点。
- **F-604 性能上限**：① 列表虚拟化——侧栏笔记列表超过 300 条启用 `@tanstack/vue-virtual` 动态测量虚拟滚动，之下保持普通渲染（两态共用同一套行标记）；② 全文搜索倒排索引——笔记数 ≥ 5000（架构文档 §8 口径）时启用 MiniSearch（拉丁整词 + CJK 单字分词，AND + 前缀 + 标题加权），构建走 Dexie 游标流式读取、启动空闲 2s 后补建（构建期间查询自动回退流式扫描），保存/新建/删除/恢复增量维护，同步整库刷新后丢弃重建；③ 启动时间预算——`performance.mark/measure` 打点（模块求值 → 挂载 → 列表就绪）输出控制台，非关键路径（持久化申请/自动同步/索引构建）全部让路首屏。
- **F-605 扩展点评估**：结论见 ARCHITECTURE ADR-011——命令注册表（已落地）与 CodeMirror 扩展组（setup.ts）为当前两个稳定扩展缝；运行时第三方插件加载器（安装/沙箱/版本协商）明确不在 v1.0 范围。

## 10. 后续阶段规划 —— v1.1 → v2.0（规划稿，2026-10-27 定稿）

### 10.1 v1.1 —— 双链与知识网络（已实现）

> 目标：把「文件夹/标签的分类式组织」升级为「笔记间的显式连接」，给重度写作用户提供知识抓手。双链是**纯 Markdown 文本约定**（正文字符串），无任何 schema 变更，天然随备份/同步/快照全链路工作——这是本版风险最低的「大功能」。

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-701 | 双链协议与解析 | 语法 `[[标题]]`（渲染时按标题精确匹配）与别名 `[[标题\|别名]]`；预览内双向可点击：命中 → 路由跳转目标笔记（同名多篇时候选列表消歧）；未命中 → 点击**新建同名笔记**消除断链。编辑器输入 `[[` 唤出标题补全浮层（复用 CodeMirror 扩展缝 setup.ts，按最近更新排序、↑↓/Enter/Esc 键盘导航）。重命名笔记时提供**「更新全部引用」一键迁移**（Dexie 游标流式扫描全库替换 `[[旧标题]]`，失败不落库）。导出 `.md` 与备份保留原文字面量（遵循 Obsidian 等通用约定，第三方工具可读） | 无 schema 变更 |
| F-702 | 出入链接面板 | 编辑器侧栏新增「链接」页签：**反链**（引用了当前笔记的笔记列表，逐条引用行 ±40 字摘要，复用搜索摘要口径）与**出链**（当前笔记引用的目标，断链标记区分）；点击行即跳转。链接索引为**内存派生数据**：正文正则流式扫描构建，保存/删除/恢复/同步整库刷新时增量维护，不落库、可随时重建（与 MiniSearch 索引同原则） | 无 |
| F-703 | 关系图谱 | 新增 `/graph` 路由：自研轻量力导向图（SVG + requestAnimationFrame，不引入 D3 量级依赖）；节点 = 笔记（文件夹着色、半径按链接度），边 = 双链；数据复用 F-702 链接索引；点击跳转、hover 高亮邻接、缩放平移；大库降级：默认仅渲染当前文件夹/搜索过滤的子集（≤ 500 节点），全库模式显式提示阈值与冻结风险 | 无 |

**验收要点**：六个场景双链语义不坏——重命名（执行「更新引用」迁移后反链准确）、删除后恢复（链接语义复原）、回收站内笔记不产生有效出链（与索引排除口径一致）、双端同步后链接一致、备份导出导入往返后 `[[ ]]` 字面量无损、快照回滚（含链接文本）后反链面板即时一致；图谱在 3000 篇级不冻结（过滤/降级生效）。
**本版明确不做**：`![[...]]` 嵌入语法（引用块式渲染）、链接关系落库建表、图谱全库实时动画巡游、无 `[[ ]]` 字面量时的「自动感知链接」。
**工程搭车**：E-01 打包拆分（§10.6）——MiniSearch 动态 import + manualChunks（vendor/editor/markdown/minisearch/virtual 分 chunk）已落地、GraphView 路由级分包；vue-virtual 组件化惰性挂载与 i18n 字典拆载（同步 t() 需预载语义，影响面大）延续为 E-01 观察项，gzip 基线 ≤ 0.5MB 保持。E-04 CJK bigram 精度如反馈出现即时评估。

### 10.2 v1.2 —— 导入互操作（已实现）

> 目标：给二手数据（Evernote / Notion / 散装 Markdown）体面的「进场」通道。导入一律**全量插入**（不与既有笔记智能合并），完成后输出统计摘要（成功/跳过/失败计数与明细），不做跨库去重（按需求再评估）。

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-801 | Markdown 批量导入 | 数据菜单入口 + 整页拖拽：多选 `.md` 与 zip（`notes/` + `assets/` 目录结构）；标题取首个 H1（缺失回退文件名）；zip 内图片按相对路径重链为内部附件；目录结构映射单层文件夹（二级目录起平铺，层级关系以标题层级保留在一篇内）；产物走既有导入校验口径 | 无 schema 变更 |
| F-802 | 富文本粘贴转 Markdown | 编辑器拦截 `text/html` 粘贴（turndown + GFM 插件，**动态 import 惰性加载**）：标题/列表/表格/加粗/斜体/链接/行内代码映射；剪贴板内图片走 v0.3 附件管线；`Ctrl+Shift+V` 保持纯文本粘贴行为不变；复杂结构（跨页表格、脚注）降噪为纯文本并写入已知限制 | 无 |
| F-803 | Evernote ENEX 导入器 | 选择 `.enex` 文件：DOMParser 解析 ENML → Markdown（复用 F-802 转换内核）；`<resource>` → 附件（图片白名单，v1.4 F-1003 扩白名单后自然扩大）；`<note-attributes>` 的来源 URL 写入正文首部 blockquote 元信息（不新增字段）；笔记本名映射文件夹；原生标签直接映射 | 无 |
| F-804 | Notion 导出 zip 导入器 | 解析 Notion「Markdown & CSV」导出包：页面 md + `<uuid>-<hash>.png` 等附件重链；嵌套子页 → 以标题层级平铺并保持内容连续；数据库 csv → 每行一篇笔记（文本属性映射标签、日期属性映射创建/更新时间、公式列取纯文本、不支持类型跳过并计数）；`Untitled` 空壳页跳过 | 无 |

**验收要点**：三套 fixture（纯 md zip / ENEX / Notion 导出包，均含中文与图片）导入后笔记数量一致、图片可显示、标题/标签/时间映射正确、全量备份往返无损；Word 与网页两种源的粘贴样本结构保持、图片落附件库。
**本版明确不做**：导出回 Evernote/Notion 格式、导入智能合并与去重、任何服务器中转。
**工程搭车**：E-02 Playwright E2E 首套（冒烟 + 导入链路）；E-05 F-504 本地文件夹直连在本版做转正/继续搁置决策。

**v1.2 实现口径补充**：

- **入口与摘要**：数据菜单「导入文件」（.md 多选 / .zip / .enex，zip 按内容识别——含 csv 即 Notion 包、否则按 Markdown 包）+ 整页拖拽；导入弹窗展示成功/跳过/失败计数与明细，进行中忽略新触发；完成后列表/文件夹/派生索引整库刷新（与备份恢复同口径）。
- **F-801 口径**：标题取首个 H1（缺失回退文件名，H1 为首行时从正文剥离）；zip 顶层 `notes/` 视为容器不建文件夹，其下一级目录映射文件夹，二级目录起平铺（每层目录前置为对应级别标题保留在一篇内）；图片按「原文 / 解码 / 文件名」三键匹配重链为附件（图片白名单 + 10MB 上限，超限计入跳过）。
- **F-802 口径**：capture 阶段拦截（CodeMirror 的 paste 处理在 contentDOM，气泡阶段已写入纯文本会双插）；剪贴板 html 有正文文本走转换、否则文件图片走 v0.3 管线；`data:` 内嵌图片落附件库、`http(s)` 保留外链、`file:/blob:` 不可达引用丢图；转换失败回退纯文本插入。
- **F-803 口径**：ENML 自闭合标签先展开为显式开闭标签再按 HTML 解析（未知元素非 void，否则后续兄弟被吞进子树）；ENEX 紧凑 UTC 时间（`YYYYMMDDTHHMMSSZ`）解析；来源 URL 进正文首部 blockquote；文件夹取自文件名（ENEX 按笔记本逐个导出的约定，格式内无笔记本字段）。
- **F-804 口径**：嵌套子页平铺内联进父页正文（标题层级随深度降级、超 6 级封顶），页间 `.md` 链接降噪为纯文本；csv 日期列按列名优先（created/创建 → createdAt，modified/updated/修改/编辑/更新 → updatedAt）、按值启发式兜底（全列可解析为日期才判定），文本属性映射标签（短单行值），公式列取 csv 纯文本进属性表，空标题行跳过计数。
- **搭车修复（E-02 发现）**：F-102 自动保存竞态——persist 在 `await` 恢复后把 `savedContent` 标记为 `content.value`，保存落库期间的新键入被误标为已保存、刷新即丢（v0.1 起即存在）；修复为入口快照草稿、标记本次实际保存的快照。

## 12. 发布流程与工程纪律

1. 每个版本从 `main` 拉出 `<version>-dev` 分支推进，完成合并回 `main` 并打 tag 自动部署。
2. `CHANGELOG.md` 按版本记录：新增功能点编号、数据 schema 变更、迁移说明、已知问题。
3. schema 迁移必须有单测：以旧版本备份文件为 fixture 回放导入。
4. 部署流水线中 `npm run test:run` 为硬门禁，测试不过不发布。
5. 砍掉或延后的功能点**保留编号并标注状态**（如 `F-504 已搁置`），保证决策可追溯。
