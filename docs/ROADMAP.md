> 版本：v1.0 ｜ 日期：2026-10-23 ｜ 状态：已定稿
> 配套文档：[技术架构文档](./ARCHITECTURE.md)

## 1. 迭代原则

1. **每个版本独立可用、可发布**：不做半成品功能进主线；一个版本 = 一次 git tag + CHANGELOG 记录。
2. **数据安全优先于新功能**：任何版本发布前，"导出备份"链路必须可用；先保证不丢数据，再谈加功能。
3. **数据 schema 只增不破**：新字段一律可选（`?`），旧数据经迁移函数升级；备份格式带 `schemaVersion`，导入向后兼容。
4. **小步快跑**：每版 2–4 周量级；功能点带编号（F-xxx），变更与砍掉的功能记录在 CHANGELOG，避免范围膨胀。
5. **每版有可验收标准**：功能点描述"做完长什么样、怎么测"，验收不过不发布。

## 3. v0.1 —— MVP：能记

> 目标：跑通"记录 → 自动保存 → 找回"闭环，上线第一个可用版本。

| 编号 | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F-101 | 笔记新建/编辑/删除 | textarea 编辑器 + 标题栏；删除走确认弹窗，数据层软删（`trashed`），为 v0.2 回收站铺路 | 新建出现空笔记并可输入；删除后从列表消失且库中留痕 |
| F-102 | 自动保存 | 输入防抖 800ms 写库 + 失焦立即保存 + 关页强制 flush；无保存按钮 | 输入后**不点任何按钮**直接刷新页面，内容仍在 |
| F-103 | Markdown 实时预览 | 编辑/预览分栏或切换；支持 GFM 基础：标题、列表、代码块、链接、引用 | 常见语法渲染正确；原始 HTML 不被执行（安全要求） |
| F-104 | 笔记列表 | 按 `updatedAt` 倒序；展示标题 + 内容摘要 + 相对时间 | 新建排序置顶；摘要截断无样式泄漏 |
| F-105 | 全文搜索 | 大小写不敏感的包含匹配，命中标题与正文，标题命中优先 | 搜索词能命中标题笔记与正文笔记；输入防抖不卡顿 |
| F-106 | 主题 | 深浅色跟随系统（`prefers-color-scheme`），可手动切换 | 切换即时生效并持久化 |
| F-107 | 数据落库 | Dexie/IndexedDB schema v1（见架构文档 4.2） | 重复打开应用数据稳定；DevTools 可见 notes 表 |

**本版明确不做**：文件夹、标签、回收站 UI、导出、PWA。
**发布门槛（E2E）**：新建→输入→刷新数据在；导出 JSON→清库→导入还原（手动走一遍）。

## 4. v0.2 —— 组织与效率

> 目标：笔记超过几十篇后依然找得到、管得住。

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-201 | 文件夹（单层） | 侧边栏文件夹树（仅一层）；拖拽/菜单移动笔记 | `folderId` 字段启用，schema 不变 |
| F-202 | 标签 | 笔记内打标签；侧边栏标签云；点标签过滤 | `tags` 字段启用 |
| F-203 | 置顶 | 置顶笔记在列表最前 | `pinned` 字段启用 |
| F-204 | 回收站 | 查看软删笔记，支持恢复/彻底删除；**30 天自动清理**（启动时惰性执行） | `trashedAt` 字段启用 |
| F-205 | 搜索增强 | 命中关键词高亮；按文件夹/标签过滤；显示结果数 | 无 |
| F-206 | 快捷键 | `Ctrl+N` 新建、`Ctrl+K` 聚焦搜索、`Ctrl+E` 切换预览、`Ctrl+D` 删除（带确认） | 无 |
| F-207 | 统计信息 | 字数/字符数、创建与更新时间展示 | 无 |

**验收要点**：回收站恢复后笔记回到原文件夹且标签完整；30 天清理的单测覆盖（注入当前时间）。

## 5. v0.3 —— 编辑体验升级

> 目标：从"能用"到"好用"，并补齐数据安全的出口（备份）。

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-301 | CodeMirror 6 编辑器 | 基于 vue-codemirror 封装：语法高亮、可选行号；编辑滚动与预览滚动联动 | 无（编辑器封装替换，store 不感知） |
| F-302 | 大纲（TOC） | 预览态侧边栏展示标题大纲，点击跳转 | 无 |
| F-303 | 图片粘贴/拖拽 | 粘贴/拖入图片 → 存为 Attachment（Blob）→ 正文插入内部引用 `tinynote-attachment://<id>`，预览时解析为 blob URL | **新增 attachments 表（schema v2 迁移）** |
| F-304 | 导出 Markdown | 单篇导出 `.md`；全部笔记导出 zip（`notes/*.md`） | 无 |
| F-305 | 全量备份/恢复 | 导出 `tinynote-backup.zip`（manifest.json + notes + assets）；导入时校验 `schemaVersion`，旧版本走迁移 | **备份格式升级为 zip** |
| F-306 | GFM 增强 | 表格、任务列表、脚注、删除线在预览中完整支持 | 无 |

**验收要点**：粘贴图片后清库，用 v0.3 备份包还原，图片可显示；导入含 v0.1 JSON 备份（fixture）成功迁移。

## 6. v0.4 —— 可靠性与 PWA

> 目标：把"丢数据"的风险降到最低，并支持离线安装使用。

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-401 | PWA | vite-plugin-pwa：离线打开、安装到桌面；app shell 缓存 + 构建产物预缓存 | 无 |
| F-402 | 历史版本快照 | 检测到"大变更"（如距上次快照字符变化 >20%）自动快照；支持手动快照与回滚；保留上限 20 条/篇 | **新增 snapshots 表（schema v3 迁移）** |
| F-403 | 备份提醒 | 距上次导出 >7 天时启动横幅提醒（可关闭） | settings 新增 `lastBackupAt` |
| F-404 | 版本更新提示 | 检测到新版本 Service Worker 后提示"刷新以更新" | 无 |
| F-405 | 存储持久化申请 | 启动时调用 `navigator.storage.persist()`，降低被浏览器清理概率；显示当前用量 | 无 |

**验收要点**：断网状态下应用可完整打开并编辑；发布新版本后旧用户能看到更新提示。

## 7. v0.5 —— 同步与多设备

> 目标：两台设备之间数据可达，仍不引入任何自建服务器。

| 编号 | 功能点 | 说明 | 数据影响 |
| --- | --- | --- | --- |
| F-501 | GitHub Gist 同步 | 用户配置 PAT（存本机），把全量数据（可加密）存入私有 Gist；手动/进入时自动触发同步 | settings 新增同步配置项 |
| F-502 | 冲突处理 | 以 `updatedAt` 为准 last-write-wins；检测到双侧都变更时保留冲突副本（`<标题>(冲突@设备)`）供手动合并 | 冲突副本即普通笔记，无 schema 变更 |
| F-503 | 同步加密（可选） | Web Crypto AES-GCM，密码经 PBKDF2 派生密钥后加密备份内容再上传 | Gist 内容格式新增加密包装 |
| F-504 | 本地文件夹直连（探索） | File System Access API 把笔记库指向本地文件夹（.md 文件直接落盘）；浏览器支持度有限，标注实验特性 | 视结果决定是否转正 |

**验收要点**：两台设备（或两个浏览器 Profile）通过 Gist 完成一次双向同步且无静默数据丢失；加密开关打开后 Gist 内容不可读。

## 10. 发布流程与工程纪律

1. 每个版本从 `main` 拉出 `<version>-dev` 分支推进，完成合并回 `main` 并打 tag 自动部署。
2. `CHANGELOG.md` 按版本记录：新增功能点编号、数据 schema 变更、迁移说明、已知问题。
3. schema 迁移必须有单测：以旧版本备份文件为 fixture 回放导入。
4. 部署流水线中 `npm run test:run` 为硬门禁，测试不过不发布。
5. 砍掉或延后的功能点**保留编号并标注状态**（如 `F-504 已搁置`），保证决策可追溯。
